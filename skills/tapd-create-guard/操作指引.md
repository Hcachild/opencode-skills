# TAPD 创建工作项必填字段校验 · 操作指引

> 本文件随技能一起分发，供**使用本技能的人**阅读。
> 适用对象：通过 WorkBuddy / AI 助手向 TAPD 创建、批量创建、复制工作项（Epic / Feature / Story / Task）的同学。

---

## 一、这个技能解决什么问题

TAPD 系统**只在状态流转时**校验必填字段，**创建时并不校验**。通过 API / MCP 创建工作项会绕过这层约束，历史上产生过大量「字段全空」的空壳工作项（如知识库 v1.3 那批任务）。

本技能在创建前补上这道闸：

- ✅ 创建前**强制校验全部必填字段**（缺一个都不让建）
- ✅ **层级铁律**：Epic→Feature→Story→Task 逐级挂载，禁止同级 / 越级挂载
- ✅ **全量确认**：AI 先出完整草稿（含标题、详细描述全文、全部必填字段），你确认后才建
- ✅ **创建后回执**：按 ID 回读实际写入值，逐字段核对，防止「返回成功但没真写进去」
- ✅ 同步覆盖**修改前 / 状态流转前 / 删除前**的安全校验

## 二、怎么装

把整个 `tapd-create-guard/` 文件夹放到技能目录下即可，**无需额外配置、无需装第三方依赖**（脚本为纯 Python 标准库实现，macOS / Windows 通用）：

| 平台 | 个人级安装位置（推荐，所有项目通用） | 运行脚本用 |
|---|---|---|
| **macOS / Linux** | `~/.workbuddy/skills/tapd-create-guard/` | `python3` |
| **Windows** | `C:\Users\<用户名>\.workbuddy\skills\tapd-create-guard\` | `python` |
| 项目级（仅本项目成员） | `{项目}/.workbuddy/skills/tapd-create-guard/`（两平台同） | 同上 |

放置后，下次对话让 AI「创建 TAPD 需求 / 建任务」等，它会**自动加载**本技能并按流程走。

> 目录结构（分发时保持完整）：
> ```
> tapd-create-guard/
> ├── 操作指引.md                    ← 本文件
> ├── SKILL.md                      ← 技能规则（AI 读取）
> ├── scripts/                      ← 6 个校验脚本
> │   ├── validate_required_fields.py   # 创建前必填+层级+模板+枚举校验
> │   ├── creation_receipt.py           # 创建后字段核对回执
> │   ├── backfill_epic_project_field.py# cf36 存量空缺回填计算
> │   ├── update_change_guard.py        # 修改前变更安全校验
> │   ├── transition_guard.py           # 流转前必填校验
> │   └── delete_guard.py               # 删除前关联影响评估
> └── _guard/                       ← 更新保护（见第八节）
>     ├── guard.json
>     └── verify.py
> ```

## 三、触发方式

直接用自然语言告诉 AI 你要做什么即可，AI 会自动调用本技能。常见触发词：

> 创建 TAPD 需求、建 Story、建 Epic、建 Feature、新建任务、批量创建需求、批量建任务、复制需求到 TAPD、TAPD 创建工作项、需求录入 TAPD、建缺陷、创建缺陷、提缺陷、提 Bug、录缺陷……

**你只需要给出业务信息**（要建什么、父需求是哪个、大概的负责人 / 时间），**必填字段的草稿由 AI 帮你填好**，你确认即可。

## 四、你（使用方）需要知道的铁律

这几条是 AI 必须遵守的，你也据此监督它有没有偷懒：

1. **一切以你提供的材料为准** —— 写入 TAPD 的信息都必须来自你给的内容（对话内容、你指定的文档 / 链接、TAPD 已有数据）；材料之外靠推断 / 经验得出的值会标「建议 / 推断」，**经你确认后才能写入；没有你的确认，AI 不会对 TAPD 做任何写操作**（创建 / 修改 / 流转 / 删除 / 评论 / 登记工时）。
2. **缺字段不许建** —— 任一必填缺失，AI 会先按理解填成「建议值」给你确认，而不是先建后补。
3. **层级不能乱挂** —— Task 的父只能是 Story，Story 的父只能是 Feature，Feature 的父只能是 Epic；Epic 无父。
4. **必须全量确认** —— AI 会一次性把「字段表 + 描述全文 + 层级 + 校验」全摆给你；**你改了任何一处，它会把整版重新摆一遍再请你确认**。
5. **配置 / 枚举只读** —— 优先级、分类、任务类型等枚举只能选 TAPD 里已存在的选项，AI 不会自己造值。
6. **修改 / 流转 / 删除也要确认** —— 改字段（含缺陷修改）、改状态（含缺陷流转）、删工作项前，AI 都会先列清单 / 关联影响给你确认；用户改了任何一处，清单会完整重列再确认一遍。
7. **账号一致** —— 所有写操作使用授权 TAPD 账号；但处理人等业务字段按实际填，不算冒名。

## 五、标准操作流程（你看到的部分）

AI 内部按 7 步执行，你主要参与**第 5 步确认**和**第 6 步说"创建"**：

| 步骤 | AI 做什么 | 你要做什么 |
|---|---|---|
| 0 | 确认授权账号 | — |
| 1 | 暂不调用创建接口 | 把需求说清楚（建什么、父需求 ID） |
| 2 | 整理待创建数据 | — |
| 3 | 跑 `validate_required_fields.py` 校验 | — |
| 4 | 校验父需求层级 | — |
| **5** | **出完整草稿（全量四件套）** | **逐字段看，要改直接说改哪几处** |
| **6** | 整批创建（确认后才建） | **没问题就说「创建」** |
| 7 | 回读 + 出字段核对回执 | 看回执是否全绿 |

**第 5 步草稿示例（你看到的样子）：**

```
这是准备创建的内容（共 2 条），请逐字段确认；不改就说「创建」，要改直接指出改哪几处。

【1】Task「开发-询价接口客户信息非必填改造」
· 必填字段
  | 字段 | 草稿值 | 来源 |
  |---|---|---|
  | 标题 | 开发-询价接口客户信息非必填改造 | 按 Task 标题模板 |
  | 详细描述 | 见下方全文 | AI 起草（三段模板） |
  | 父需求 | 【价格表管理】支持批量询价导入（…909） | 你给的 Story |
  | 任务类型 | 开发 | 建议 |
  | 优先级 | P2 | 建议 |
  | 处理人 | 张岩 | 建议 |
  | 预计开始/结束 | 2026-10-14 / 2026-10-16 | 建议 |
  | 预估工时 | 16 | 建议（≤24h 无提示；>24h 会提示与主管确认） |
  | Epic归属项目或系统 | 财务专项 | 按父级继承 |
· 详细描述（全文）……（一、任务说明 / 二、完成定义 / 三、依赖）
· 层级：Epic『财务专项』› Feature『价格表管理V1.0』› Story『…』› Task（本条）
· 校验：必填 9/9 已覆盖 ✓ ｜模板：符合 ✓
```

**确认口径：**
- 你说「创建 / 可以 / 没问题」且没提任何修改 → AI 才创建；
- 你指出要改哪几处 → AI 改完**把整版重新摆一遍**，你再确认；
- 只说「改一下 X」≠ 确认，改完还要再确认一次。

**创建缺陷时多一步**：AI 会先问你在哪个空间（`36495762` 生产缺陷处理 / `32496738` 需求池）——两空间必填字段清单不同，你确认空间后它才出草稿；你没说空间它不会自作主张默认。

## 六、各类型必填字段速查

> 标题（name）各类工作项都要。Story / Task 的「详细描述」也必须填（不能空壳）。

| 类型 | 必填项（数量） |
|---|---|
| **Epic 史诗故事** | 标题、项目分类、优先级、处理人、项目Owner、Epic归属项目或系统（6） |
| **Feature 特性** | 标题、父需求(必须Epic)、优先级、处理人（4） |
| **Story 需求** | 标题、详细描述、父需求(必须Feature)、分类、需求提出方、需求类型、优先级、处理人、计划需求评审时间（9） |
| **Task 任务** | 标题、详细描述、父需求(必须Story)、任务类型、优先级、处理人、预计开始、预计结束、预估工时（9） |
| **Bug 缺陷** | 两空间清单不同：**生产缺陷处理 36495762**＝标题+6 项（严重程度、开发人员、处理人、所属系统、缺陷提出方、问题来源）；**需求池 32496738**＝标题&内容+7 项（关联需求、严重程度、处理人、开发人员、缺陷类型、迭代、引入阶段，手册第 4 章）。**标题模板两空间不同**：生产缺陷=【系统名称】【模块或功能名称】描述；需求池=【系统名称 版本号】描述。**描述模板两空间相同**：【环境】【版本】【复现步骤】【预期结果】【实际结果】【附件】分条换行（AI 自动套用并校验）。不走父需求层级校验，但需求池缺陷必须关联需求；**标题/描述全文与必填字段一次性全量确认**（改任何一处整版重展）；**权限不足、账号、材料等强制规则与其他类型完全一致**；流转必填以 TAPD 工作流实查为准 |

**几个易错点（AI 会帮你避开，你也可核对）：**
- ⚠️ `category_id`（分类）创建时**必须传数字 ID**（如技术需求=`1132496738001000029`），传中文会被静默写成 `0` 而接口不报错。
- ⚠️ 任务上的「分类」(`category_id`) **不是任务必填**；任务必填的是「任务类型」(`custom_field_19`)。
- ⚠️ `effort` 单位是人小时（h），**>24h 会弹出提示「请与主管确认工时的合理性」**（≤24h 不提示；提醒不阻断，允许存在超过 24h 的任务）。
- ⚠️ 日期格式 `YYYY-MM-DD`。
- ⚠️ `Epic归属项目或系统`(`custom_field_36`) 会沿父级自动继承，你一般不用手填。
- ⏰ **计划时间有先后链** —— 任务：预计结束 ≥ 预计开始；Story：计划评审 ≤ 开发开始 ≤ 提测 ≤ 测试开始 ≤ 测试完成 ≤ 上线。填倒挂了 AI 会醒目提醒；你确认坚持原值就放行（提醒不拦人）。

## 七、配套脚本（AI 自动调用，你通常不用管）

| 脚本 | 何时跑 | 作用 |
|---|---|---|
| `validate_required_fields.py` | 创建前 | 校验必填 + 层级 + 模板 + 枚举（含缺陷 Bug）；退出码 0=通过，1=不得建 |
| `creation_receipt.py` | 创建后 | 回读实际值逐字段核对，输出 ✓/✗ 回执 |
| `backfill_epic_project_field.py` | 存量空缺修复 | 算 `custom_field_36` 逐级回填清单 |
| `update_change_guard.py` | 修改前 | 区分补空/覆盖/系统自动字段，覆盖需你确认 |
| `transition_guard.py` | 流转前 | 校验该次状态流转的必填项 |
| `delete_guard.py` | 删除前 | 评估级联子树 / 工时 / 上游链路影响 |
| `timesheet_guard.py` | 登记工时**前+后**；亦可做**全周期审计** | 校验单人单日合计（>12h 提示「请与主管确认工时的合理性」；如需调整可修改 / 分摊到其他日期，用户坚持才放行）。**登记完成后会强制复查**一遍当天全空间工时——别人可能刚好同天也登了。**审计模式**：拉某账号近 2 个月全部工时跑 `--owner --since --over-only`，列出所有超 12h 的日期明细 |
| `owner_match_guard.py` | 修改 / 流转 / 删除前 | 检查对象的人员（处理人 / 产品经理 / 测试人员 / 开发人员 / 需求提出方等）是否与当前账号有关——全无关则醒目提醒「人员跟你不匹配，确定要操作么」，你强制确认才放行 |

> 💡 **工时分摊批量登记**：告诉 AI「给某个任务登记 X 小时，从某天开始」，它会自动按每天 8h 拆成多条不同日期的工时记录（默认跳过周六日，**并提醒你核对法定节假日 / 调休**——你可以直接指定要跳过的日期），校验当天合计不超 12h，给你确认后批量写入并回读核对。

## 八、关于更新保护（_guard）

本技能受**更新保护**：任何对 `SKILL.md`、`scripts/`、`_guard/` 的修改，AI 都会先要求输入更新密码，**密码由作者持有**，脚本只存哈希、不留明文。

- 你（接收方）**正常使用、让 AI 创建需求**完全不受影响，无需密码；
- 只有当你要求 AI「改这个技能本身的文件」时才会触发密码校验；
- 若确需修改技能，请联系作者获取密码，或自行移除 `_guard/` 目录（移除即放弃保护，后果自负）。

## 九、空间相关配置（按需调整）

本技能内置的枚举值、工作项类型 ID、必填清单基于**两个 TAPD 空间**实测配置：

- **需求池（百运与中技公共）`workspace_id = 32496738`**：Epic/Feature/Story/Task 四类 + 需求池缺陷（标题&内容 + 7 项）
- **生产缺陷处理 `workspace_id = 36495762`**：缺陷（标题 + 6 项）—— 必填清单、流转必填、标题模板与需求池缺陷**不同**
- 授权账号：**由 `get_current_user` 实时确定**（技能不写死姓名 —— 谁的 TAPD 凭证配置在当前环境，授权账号就是谁；处理人等业务字段仍按业务实际填别人）

**若用于其他 TAPD 空间**：枚举选项、字段 ID、workspace_id 可能不同，需按目标空间实际配置调整 `SKILL.md` 中的取值速查与脚本内的枚举清单（调整后建议重跑校验脚本确认）。

## 十、一句话总结

> 你提业务需求 → AI 出完整草稿 → 你确认 → AI 创建 → AI 出回执核对。
> 中间任何一步缺字段、层级错、没确认，AI 都不会动 TAPD。
