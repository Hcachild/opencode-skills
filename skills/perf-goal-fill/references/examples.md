# 正例与反例

## 黄金正例（已定稿，照这个密度写）

| 模块/目标 | 具体内容 |
|---|---|
| 可观测链路/监控 | 在测试环境上线平台监测模块：每次对话执行后，经 Outbox 把记录异步投递到监测后台，页面能对应到本次使用的发布、部署和模型，并查看是否成功、耗时、用量和积压。监测服务异常时对话主流程仍可用，记录先积压、恢复后再补送。配套完成测试机从轻量库切到 PostgreSQL、监测栈按独立仓库部署，输出部署方案和验收说明。 |
| Agent监测工具评测与选定 | 评测多套开源监测工具，目前选定五套试用：Langfuse、Phoenix、Laminar、AgentOps、OpenLIT。分别在测试机部署，用同一批对话执行记录做对照，比较资源占用、部署运维成本、页面能否还原工具调用和对话过程。输出一份监测链路选型调研文档，给出测试环境推荐方案和取舍说明。 |

这段为什么过关：

- 是「要做」：上线、投递、验证、切换、输出。
- 有可点名交付：监测模块上线、PostgreSQL、独立仓库、部署方案、验收说明、调研文档。
- 英文只有 Outbox、PostgreSQL、五个产品名。
- 没有票号、没有内存数字、没有「三足鼎立 / 明确不试」。

## 同一条的失败稿（不要再写成这样）

落地 AaaS 最小可观测闭环（TAPD P1A-T07 / E08-T01~T05，9/1 关闭）：L1 Trace 贯通 Execution/Attempt/Release/Deployment/Replica/Model Binding；Outbox 异步投影到可替换 ObservabilitySink；GET /metrics 暴露积压、错误、Token、成本、延迟；观测后端故障 fail-open，不阻塞主链路。测试机完成 Postgres 配置切换（零代码）、独立仓部署观测栈、Nginx :8080 公网 UI；AAAS_OBS_BACKEND 可秒切后端；多次 verify-stable-dev live execution 全绿。产品路径维持 L1，L2 默认关闭。

评测 5 个后端：Langfuse（~2.2GiB，过重）→ Phoenix（~228MiB，L1 闭环）→ Laminar（~757MiB）→ AgentOps（无现成镜像、构建成本高，弃用）→ OpenLIT（~459MiB，OTLP 原生）。结论：Phoenix / Laminar / OpenLIT 三足鼎立，其余明确不试；生产方案仍待 decisions.md §3.9，不把测试机选型当生产承诺。

问题：票号、结果数字、内部命令、夸张结论、推脱、像在向模型交差。
